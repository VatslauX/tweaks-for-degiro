# Integration and E2E test fixtures

## Integration tests

`tests/integration/*.test.js` run the real isolated-world scripts in manifest order against mock pages in JSDOM, without a browser. `tests/integration/harness.js` provides:

- `createWorld({ storage })` creates one browser profile. `chrome.storage.sync/local` is shared across tabs, values are JSON-copied, `onChanged` is asynchronous, and `world.latency`, `world.faults`, and `world.log` support timing, failure, and write assertions.
- `world.open({ fixture, hash, settings, lang, globals })` returns a tab. `globals` supplies fixture switches and data such as `__TX`, `__ORDERS`, and `__MOCK_*`. Fixture inline scripts run before extension scripts. The `portfolio` fixture's own script calls `fetch()` for its canvas-based performance chart; JSDOM has neither, so pass `globals: { fetch: () => new Promise(() => {}) }` to park that chart's `load()` at its first `await` forever — the holdings-table DOM and the extension's scripts still run normally. Only the chart itself (Highcharts/canvas) stays Playwright-only.
- Tab helpers include `tab.setPrice`, `tab.go(hash)`, `tab.setFlag(key, on)`, `tab.run(code)`, `tab.json(expr)`, `tab.owned()`, `tab.message(msg, sender?)` (delivers a `chrome.runtime` message, like the toolbar popup, and returns the reply), and `world.set(area, items)`.
- Page-world scripts (`world: "MAIN"`) run with `world.open({ page: true })`: in a `vm` context of their own (own globals, no `chrome`) over the tab's DOM and virtual clock; `tab.page.run(code)` / `tab.page.json(expr)` evaluate there. `page: true` also gives the tab DEGIRO's network: `fetch` answered by `tests/fixtures/mock-api.js` (the same answers and `calls` counters as the e2e route; `orders` and `respond(url)` as in `degiro()`, `'hang'` waits until the request's signal aborts), resource-timing entries and `PerformanceObserver` for every answered request (`tab.resource(href)` adds one), `AbortSignal.timeout` on the virtual clock, a visible tab, `tab.calls` and `tab.requests` (paths asked for). With it the portfolio fixture's own `fetch()` is answered too, so the `globals.fetch` parking above isn't needed. `highcharts: true` loads the real Highcharts from `node_modules` before the fixture's scripts (with a per-character SVG text box, since JSDOM has no `getBBox`). `layout: true` is a stand-in for layout and canvas: every shown page element measures 1000 × 400 at the top left, the extension's own `[data-dg-own]` elements 0 × 0, and canvases get a 2D context that draws nothing and reads back blank pixels; enough for code that asks whether something is shown, never for sizes or positions. `localStorage: { key: value }` seeds the DEGIRO origin's localStorage before any script runs (e.g. `dgTweaksCashLines`). Examples: `tests/integration/requests.test.js`, and the page-world sections of `orders.test.js` and `alarm-lines.test.js`. The older tests that load page-world scripts by hand over a small JSDOM page (`period.test.js`, the top of `orders.test.js` and `alarm-lines.test.js`) still work that way.
- `Date`, timers, and `requestAnimationFrame` share a virtual clock. Use `world.advance(ms)` to run timers, frames, promises, and storage events in order; `world.skip(ms)` to jump time; `world.flush()`/`tab.flush()` to settle work due now. End a test with `noErrors(world)` from the harness: no uncaught error, and no feature in an open tab whose `run()` threw (`tab.failed()`, both worlds; the scheduler only records that as the status `'error'`). The harness also exports the alarm-data readers `events(w)`, `stateOf(w, id)`, `listOf(w)` and `banners(tab)`.
- To prove a test fails without a change, point `DGT_EXTENSION_DIR` at a scratch copy of `extension/`; never deliberately break the working source tree.
- JSDOM has no layout. Use Playwright E2E tests for sizes, visibility, sticky header choice, sidebar fit, menu clamping, computed colors, and options-page layout. Use integration tests for logic across inputs, tabs, races, and time. Extend fixtures when a feature relies on new DEGIRO DOM.

## E2E tests

`tests/e2e/fixtures.js` launches persistent Chromium (`--headless=new`) with the unpacked extension and routes all `trader.degiro.nl` requests to local mocks. Tests do not touch the real DEGIRO site.

- Each worker reuses one browser for up to 10 tests (`REUSE`; a launch costs about 0.5 s, and a new profile keeps `chrome.storage.sync` under its write quota). Between tests the fixture closes every tab, removes routes and cookies, and clears the extension's sync and local storage. A failed test discards its browser. A test that changes the browser itself (for example switching the extension off) uses `test.use({ freshBrowser: true })`. `lang` is a worker option: set it with a top-level `test.use({ lang })` in its own file.
- The fake clock (`degiro({ clock: true })`) reaches page-world timers only. Isolated-world timers and `AbortSignal.timeout` run in real time; a test can route `AbortSignal.timeout` through `setTimeout` in an `initScript`. The product fixture is `tests/fixtures/degiro.html`, with Highcharts from `node_modules` and the orders endpoint answered from the `orders` option.

- **Wait for conditions, not guessed durations.** Use Playwright's auto-waiting assertions (`await expect(locator)...`) for UI state and `expect.poll(async () => ...)` for state that has no locator. Do not use `page.waitForTimeout()` just to give the page or extension time to update. For timer-driven behavior, prefer Playwright's clock or the integration harness's virtual clock. Keep real-time delays only when elapsed time itself is under test (for example, performance sampling or a deliberate input cadence); document why the delay is needed. Assertion and test timeouts are upper bounds for failure, not substitutes for a condition.

- `degiro({ orders, url, initScript, respond })` returns `{ page, calls }`. `respond(url)` can return `route.fulfill` options (for example a 401) or `'hang'`.
- Product mock switches: `__MOCK_NO_URL_SESSION`, `__MOCK_MAIN_SECTION`, `__MOCK_NO_HOOKS`, `__MOCK_SIDES`, `__MOCK_PANEL_LABELS`, `__MOCK_TICK_MS`, `__MOCK_NOT_FAVOURITE`, `__MOCK_ORDER_PANEL`, `__MOCK_PRICE_DASH` (the price cell shows a dash before the first read), and `__MOCK_BRIEF` (`[symbol, exchange name]` in the header line, e.g. `['DE000SU054L9', 'Societe Generale OTC']` like DEGIRO's SG products). It also has a sticky header copy via `window.__stickyHeader(on)` and `window.__setPrice(id, v)`. Like DEGIRO, its price line holds a hidden, absolutely placed `[data-name=measurer]` copy of the header `CurrentPrice` (same `data-id`), placed before the visible one; `__setPrice` and the other price switches update both.
- Other pages use query switches: `?mock=orders`; `?mock=favourites` (rows carry DEGIRO's `symbolIsin` span with the product's `data-id` and `exchangeAbbr` with the exchange's own id, like DEGIRO; `__MOCK_LISTS` adds lists, rows `[id, name, symbol, exchange, sign, price, isin?]`; `__MOCK_RESOURCES` lists DEGIRO's own request addresses, with the session, for `performance.getEntriesByType`, which JSDOM leaves empty) with `window.__setPrice`, `window.__showList`, `__MOCK_NO_TITLE`, `__MOCK_PRICES`, and `__MOCK_STICKY_QUERY` (DEGIRO's router: the query stays sticky inside `#/favourites…`, empty values are dropped; adds list links); `?mock=transactions` with `__MOCK_TX_LABELS`, `__MOCK_MORE_PAGES`, `__MOCK_NO_TX_TOTAL`, `__MOCK_NO_TX_FEE`, `__MOCK_TX_HEADERS`, `__MOCK_CALENDAR`, and `__MOCK_PANEL_CLOSED`. The transactions mock includes a second `[data-name=transactions]` mini list before the main table. The portfolio mock's value endpoint has no entry for today; like DEGIRO, its line data (`window.__points`) ends with a point for the browser's local date. Like DEGIRO, the oldest point (the period's start) is neither drawn nor hoverable; the others sit at the centres of equal bands (`window.__X(i)`, i ≥ 1) and the line runs flat out to both ends. The line's last point is at the live total (`window.__MOCK_TOTAL`, default 141234.56; `null` = not known yet: the header shows the placeholder `€ 0,00` and the line has no point for today; `window.__setTotal(v)` changes it while the page is open), and while the chart is hovered the header shows the hovered day's value and date instead of the total and "Today". It rebuilds its chart on in-app navigation, greys the line right of the cursor, and swaps in a blank canvas (as DEGIRO does mid-rerender) via `window.__blankCanvas()`. Its holdings rows carry a per-row `delay` (`D15`, `R`, `ED`) that sets the Delay button's modifier class, the product name sits inside an `<a href="#/products/<id>/overview">`, and Buy/Sell are wrapped in their own `div`.
- Mocks include DEGIRO's left sidebar. `settings()` opens `options.html` with every section open (it seeds the popup's `dgOptOpen` before the page loads), so tests can click any row; `settings({ collapsed: true })` opens it as a user first sees it, every section collapsed. The reset between tests clears the popup's `localStorage` too. `setFlag(page, key, on)` toggles a setting through the UI. `stubPermissions(context, opt, grant, { answerMs }?)` stubs Chrome's permission prompt for *Check in the background* (`answerMs`: the prompt answers that late). After clicking that switch, wait for it to lose `aria-disabled` before anything its pending change gates (Clear saved data disarms meanwhile); a spec that uses it calls `unstubPermissions(context)` in `afterEach`. Playwright runs six workers locally and four on CI (`workers` in `playwright.config.js`), so a real-time sample (frames, mouse moves) must count a fixed amount of work, not what fits in a time budget on a busy machine. Extend the mock when a feature depends on new DEGIRO DOM.
